# rsync除外リスト: 開発環境 → 本番環境 (kikujo.com)

開発環境(`html/`配下)を本番のWordPressディレクトリへrsyncで反映する際に、
`--exclude`で除外すべき対象と、除外が必要な理由をまとめる。

想定コマンド形式（本番のWordPressルートに向けて`html/`の中身を同期する場合）:

```bash
rsync -avz --delete \
  --exclude-from=docs/rsync-exclude-list.txt \
  html/ <PROD_SSH_USER>@<PROD_HOST>:<本番のWordPressディレクトリ>/
```

`--delete`を使う場合は特に、除外漏れがあると本番側の当該ファイルが削除される
（本番にしか無いファイルとして扱われる）ため、除外設定は事前に十分確認すること。

## 除外対象

| パス(html/からの相対) | 理由 |
|---|---|
| `wp-config.php` | DB接続情報が環境ごとに異なる。加えて開発環境では、nginxリバースプロキシ越しに複数ホスト名を扱うため`WP_HOME`/`WP_SITEURL`をハードコードしており、`WP_DEBUG`も`1`（有効）になっている。これらは本番の設定を上書きしてはいけない |
| `wp-content/uploads/` | 本番運用中にサイト管理者がアップロードした実際のメディアファイルが入っている。開発環境側のテスト用アップロードで本番の実データを上書き・削除してしまうリスクがあるため除外し、メディアは同期対象に含めない |
| `wp-content/upgrade/` | WordPressコア更新時に使われる一時作業ディレクトリ。同期不要 |
| `.htaccess` | ホスティング環境（XREA等の本番共有サーバー）固有のリライトルール・セキュリティ設定が入っている可能性がある。開発環境用の内容で無条件に上書きしない（変更する場合は内容を個別に確認してから反映する） |

## 除外リストファイル例 (`docs/rsync-exclude-list.txt`)

上記のコマンド例で`--exclude-from`に渡すファイルの中身:

```
wp-config.php
wp-content/uploads/
wp-content/upgrade/
.htaccess
```

## 補足・注意点

- このリストは「開発環境の変更を無条件に本番へ持ち込んではいけないもの」を挙げている。
  逆に、開発環境で新規にインストール・追加した本番未導入のプラグインやテーマ変更は、
  意図した変更であればこの除外リストには含めない
- WordPressコア本体(`wp-admin/`, `wp-includes/`, ルート直下の`*.php`)やテーマ
  (`wp-content/themes/`)は本リストでは除外していないが、開発環境と本番でWordPress
  コアのバージョンが異なる場合は事前にすり合わせておく（意図せず本番のコアバージョンを
  変更してしまうことを避けるため）
- `--delete`オプションを使わない場合でも、除外対象を明示しておくことで誤って
  `wp-config.php`等を上書き転送してしまう事故を防げる
- 本番でのみ導入されている独自プラグイン・独自アップロードファイルがある場合は、
  このリストに追加で反映すること
